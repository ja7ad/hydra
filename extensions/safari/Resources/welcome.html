Hydra is not reachable

  1. Install the native messaging host, which is what lets the browser talk to the app: scripts/install-native-host.sh
  2. Make sure the Hydra desktop app is installed and has been opened once.
  3. On Ubuntu and other Linux distributions, Firefox and Chromium are often installed as a snap or Flatpak, which keeps each browser's profile in its own private directory rather than in ~/.mozilla or ~/.config. Hydra registers those locations itself on every launch, so simply starting Hydra once is the fix — the install script only covers a browser that has already been run at least once.
  4. Restart the browser so it picks up the newly registered host.
  5. Still stuck? Check that Hydra → Options → General has this browser ticked under Capture downloads from the following browsers.

What you get

Automatic capture

Click any download and Hydra takes it over — multi-connection, resumable, with your cookies carried along. Which file types are captured is set in Hydra → Options → File Types.

Hold Alt while clicking to let the browser keep one download.

Right-click & text selection

Right-click any link, image, or video → Download with Hydra. Or simply highlight links on a page — a floating Download with Hydra button appears. Several links at once open Hydra's batch download box.

Media sniffing

When a page plays direct video or audio files, a counter appears on the Hydra toolbar icon. Open the popup to grab any of them.

HLS & DASH streams

Segmented video shows up under Streams in the popup as one entry, not a thousand segments — with the quality, bitrate and estimated size the manifest declares. Pick a variant and Hydra fetches it. DRM-protected streams are listed as unsupported and are never touched.
